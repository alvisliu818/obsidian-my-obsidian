# Changelog

All notable changes to this project are documented here.
Format based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning follows [semver](https://semver.org).

## [Unreleased]

### Changed

- **Block-property rows align with the block TEXT (Logseq parity).** The `key:: value` row under a block used to sit at the bullet column's left edge and — on blocks with children — BELOW the children. It now indents past the bullet column AND the content padding so the property text starts exactly at the block text's x (bullet column and content padding are shared CSS variables, `--lgp-controls-w` / `--lgp-content-pad`), and the row is inserted directly under the block text, before the children.
- **Collapse carets are hover-revealed and take no layout space (Logseq feel).** The fold arrow used to sit in the document flow (16px column) and stay visible on every parent block, so rows without children had to compensate with a placeholder. The caret now floats absolutely over a reserved slot inside `.block-controls` (which every row renders) — it takes zero layout space, the bullet column stays aligned across sibling rows, and the arrow appears only while the row is hovered (with a soft opacity transition). Blocks whose children are COLLAPSED keep the caret always visible so the folded state stays discoverable; touch devices without hover also get it always visible. Applies to the in-place block-embed rows too (same `.block-caret` chrome).

### Added

- **The outline guide line hangs under the bullet and folds children (Logseq behavior).** The vertical line beside a block's children used to start at the row's left edge, visibly left of the bullet dot it belongs to. It now runs centered under that dot — starting just below it and stopping short of the last child's dot, with a small gap on both ends — and is clickable: clicking the line folds the block's children, clicking the stub again unfolds (the stub stays visible while collapsed as a second affordance next to the caret, with a widened hit area so the 2px line is comfortable to hit).
- **Code-block toolbar: a slim strip above every rendered code block (language + copy).** Static block content now wraps each rendered `<pre>` in a code-block unit with a 22px bar on top — the language name on the left (from the fence info string), a copy button on the right — so the copy icon lives in its own bar and never overlaps the code text (Obsidian's native floating copy button is hidden inside rendered blocks). Clicking it copies the code to the clipboard and flashes a check mark; works in in-place embed rows too. Dataview blocks are untouched (their DOM belongs to Dataview).
- **Code blocks scroll horizontally (Logseq parity).** Rendered code blocks no longer wrap long lines: `white-space: pre` + `overflow-x: auto` (Logseq's own `pre` behavior) in block content, in-place embed rows and the flashcard panel — a long line gets a horizontal scrollbar inside its box instead of wrapping (Dataview blocks keep their own rendering, as before). The block content column also permits shrinking (`min-width: 0`), so a long code line can no longer widen the whole outline row and push the box past the viewport with the scrollbar stranded at the page bottom — it scrolls inside its own box now.
- **Theme-independent code presentation, written in the plugin's own styles.** Themes and snippets scope their code styling to `.markdown-rendered` / body-option classes that plugin-rendered code never matches, which showed under Blue Topaz as (1) a duplicated uppercase language watermark painted via `pre::before` next to the plugin's own toolbar language label — suppressed inside plugin containers — (2) most Prism token colors never applying — the token classes are now mapped to the theme's own `--code-*` variables (keyword/string/number/function/class/operator/comment/…, with graceful fallbacks), so code shows the theme's full syntax palette everywhere the plugin renders it — (3) the code box losing its own padding: with the theme's scoped `pre` padding out of reach, the inline `code` element's left padding applied to the FIRST rendered line only, so `x = …` and `y = …` inside one block started ~7px apart. The box now carries its own padding and the code element is block-level with none, aligning every line — and (4) function calls reading as one flat color: Prism's grammars leave call sites plain (`TensorDataset(x, y)`), which the editor colors but the reading render did not — a conservative render-only pass wraps trailing identifiers before the call's `(` punctuation in `.token.function` (strings, comments and anything already tokenized are untouched), so the theme's palette reaches the editor's full color set.
- **Ordered-list prefixes align with the block text column (Logseq parity).** A block whose text starts with `1. …` used to be consumed by the markdown renderer into a real `<ol>` whose marker hung at the list padding — visibly right of the block text column. The list now renders with zero padding and in-flow markers, so the number sits exactly at the block's text column (matching the editor, where it is literal text) while keeping the theme's own marker color.
- **Obsidian-format page properties (frontmatter) fully supported in the outline.** A file whose properties are the Obsidian `---` frontmatter now shows them as the page-properties first block — dimmed `key: value` lines (keys and simple values are clickable pages), editable in place, with the Obsidian format preserved on every save (the body round-trips verbatim inside the `---` fences — lists, comments, key order; Logseq-style `key:: value` lines typed inside are normalized to `key: value`). The properties are also exposed to other plugins: frontmatter feeds Obsidian's metadata cache natively, and Logseq-format page properties (file-top `key:: value` lines, which the metadata cache never sees) are merged into `metadataCache.getFileCache`'s frontmatter so plugins like Dataview read them as native page properties — the file format stays Logseq. The merge covers both metadataCache.getFileCache(file) and getCache(path), so plugins reading either API see the props. Logseq-format properties also reach plugins that build relationships from `frontmatterLinks` (e.g. AbstractFolder sees `parent:: Book` as a real parent→child edge).
- **Community plugins' editor extensions now run in the outline editor — latex-suite works in it, including its own live math preview while typing.** The outline editor now shares Obsidian's own CodeMirror instance (the `@codemirror/*` / `@lezer/*` packages are external, per the official plugin convention) instead of bundling a private copy, and mounts every plugin-registered editor extension (`app.workspace.editorExtensions`) at lowest precedence. A custom markdown grammar extension adds Obsidian's math syntax nodes (`DollarInlineMath` / `DollarDisplayMath` / `DollarDisplayBlockMath` with `Dollar` delimiters and a `LaTeX` content child — the node names latex-suite's region detection iterates), `editorLivePreviewField` reads `true` in the outline editor (patched — the field's native default is false and the native flip effect is inaccessible), and `editorInfoField` is provided for plugins that resolve the editor through it. With those in place, **latex-suite runs unmodified in the outline** — snippets, paired-`$` highlighting, and its own live math preview tooltip while the caret is inside the equation (its `mathPreviewLivePreviewDisplay` setting covers `$$…$$` in live preview; nothing is reimplemented or replaced). While the caret is away from a math region, the outline renders it in place via MathJax (render-only), so reading-view-like display and latex-suite editing coexist.

- **`[[` / `![[` / `#` / `((` completion hints now actually appear.** The CM6 completion sources existed since v0.2.0, but every popup silently failed: each source returned its `from` at the trigger characters, so CM6's built-in filter (which matches the text between `from` and the cursor against every option's label) compared `[[`, `#` or `((` against page/tag/block labels and discarded all options — no tooltip node was ever created. This also corrects the v0.2.2 diagnosis: the CM6 tooltip layer was never broken; the sources simply returned an empty result set. All four sources now return `from` AFTER the trigger, keep the typed trigger on accept (`[[Page]] `, `#tag `, `((uuid))`, `{{embed ((uuid))}}` closes with `}}`), and use trigger-free `validFor` regexes. Slash commands (`/`) as a CM6 source are likewise fixed and are now served only in the in-place embed editor (the main editor keeps the self-drawn command menu). While a popup is active, ↑/↓/PgUp/PgDn/Enter/Tab/Esc are routed to it via a Prec.highest yield keymap; without a popup the outline keymap behaves exactly as before. Popup restyled to match the self-drawn menus (`styles.css`).
- **Bare top-level lines become first-level list items (Logseq parity).** Lines without a `- ` marker at the top of a file — plain paragraphs — now render as regular outline blocks with bullets instead of detached raw paragraphs, so they can be focused, indented, referenced and embedded like any block. Consecutive bare lines (no blank line between them) merge into ONE first-level block with soft line breaks, exactly like a paragraph becomes a single Logseq block; a blank line starts a new block. Saving a page normalizes them to `- ` items with indented soft lines (Logseq md format). Markdown/org structural lines keep their verbatim raw rendering: headings (`#`), quotes (`>`), tables (`|`), raw HTML, ordered lists (`1.`), star/plus bullets, org metadata/drawers, `$$` blocks and horizontal-rule/setext underlines. Indented bare lines remain soft continuation lines of their block.
- **Logseq-style block properties: type `key:: value` right in the editor.** Editing a block now shows its properties as `key:: value` lines below the text (dimmed, Logseq editor parity). On commit the trailing property lines are split back out into the block's props — typing a line adds a property, editing a line changes its value, deleting the line removes it — and the props row under the block updates live. Structural props (`id::`, `collapsed::`, `style::`) keep their dedicated UI and survive every commit untouched. Works in the in-place embed editor too.
- **Page properties ARE the first block (Logseq model), with consistent rendering.** File-top `key:: value` lines now parse into a real props-only FIRST BLOCK that renders as a regular outline item — bullet, focus, editing — with its properties shown as the block's CONTENT in the same dimmed `key:: value` form the editor displays, so the editing and reading states look alike (no separate card, no edit icon, no duplicated badges/rows). Clicking the block edits the properties as `key:: value` text like any other block; saving serializes the props-only first block back to the unindented file-top lines (Logseq md format). The former detached header card (and its pencil editor) is gone.
- **Full native selection context menu (native-editor parity).** Right-clicking inside the focused editor rebuilds the menu the native Obsidian editor shows over a text selection, in the same section order: Cut / Copy / Paste / Paste as plain text / Select all; Insert link and Insert external link (wrap the selection in `[[ ]]` / `[ ]()`); a **Formatting** submenu (bold, italic, strikethrough, highlight, inline code, math, `%%` comment — with checked state and toggle/unwrap semantics — plus Clear formatting); a **Paragraph** submenu (bullet/numbered/checklist toggles, headings 1–6 + none, quote — applied per selected line); an **Insert** submenu (footnote, table, callout, horizontal rule, code block, math block); and then the `editor-menu` workspace event fires with a native-`Editor`-shaped adapter over the block editor's selection, so every plugin's context-menu contribution appears exactly as it does in the native editor. The adapter exposes the live CM6 view as `editor.cm` (plus `coordsAtPos`/`cursorCoords`, session-tolerant `hasFocus`, `replaceRange`, `getCursor(from/to)` and `view.editor`) so plugin popups and apply-actions that position themselves off the caret or route through commands work — while a block editor edit session is live, `workspace.activeEditor` is a pseudo-view over the adapter (mirroring how the native editor registers itself), which is what makes e.g. Highlightr's color menu actually apply its `<mark>` wrap; unimplemented adapter members are no-ops, so a misbehaving contributor can't break the menu. Right-click outside an editor keeps the Logseq-style block menu. Works in the in-place embed editor too.
- **Slash menu = the NATIVE slash menu (Logseq parity).** Typing `/` in the block editor opens Obsidian's NATIVE slash-command menu (the core Slash commands feature, auto-enabled with the plugin) instead of a custom popup — it lists every available editor command: Obsidian core commands, this plugin's built-ins, and every plugin's editor commands, with the native fuzzy filtering. The self-drawn slash popup is retired; the self-drawn `<` angle menu stays. The plugin's own slash menu takes priority over the core slash-command plugin (when the user has it enabled) inside the block editor — our suggest triggers first and declines for native editors, so the native editor keeps its own menu; the built-in Logseq slash items (TODO/priority/props/…) lead the list and the menu is uncapped like the native one (a 50-item cap plus plugin-load-order variance used to hide both the built-ins and core commands entirely; the built-in list provider wiring was also dead code until now).
- **Tags are page references (Logseq parity).** Clicking a `#tag` in the outline opens the page of the same name — creating it when missing — instead of doing nothing useful; tags are styled like page links rather than search tags.
- **Tab / Shift+Tab inside in-place embed edits (Logseq parity).** While editing a block inside an embed, Tab and Shift+Tab now indent/outdent the edited block in its SOURCE tree (same-file embeds and page-embed rows through the live model, cross-file embeds through the owning view or the guarded disk-write path), then re-open the in-place editor on the same row. Previously the keys did nothing in embed editors.
- **Take-over scope**: new setting next to *Take over markdown files* — `All files` (previous behavior, minus exclusions) or `Only in specific folders`. In folder-scoped mode an **Included folders** list (comma-separated vault paths) decides where .md files open with the block editor; everything else keeps the native editor. Take-over decision extracted into a pure, unit-tested helper (`shouldTakeOver`); existing configs default to `all` and behave exactly as before.
- **Embed Enter writes to the source page**: Enter inside an in-place embed edit now appends the new block to the SOURCE page (Logseq md parity) instead of the host page — root rows grow a last child, child rows take a sibling below — and focus lands in the new row inside the embed.

### Added

- **Live preview (实时预览) in the block editors — always on, with a per-block "Source mode" escape hatch.** While editing a block, markdown syntax the caret is NOT touching renders in place — `**bold**`/`*italic*`/`==highlight==`/`~~strikethrough~~`/`` `code` `` drop their markers, `%%comments%%` dim, `[[links]]` render as page links (alias form shows only the alias, `![[embeds]]` stay raw), `#` headings take their sized form, `---` becomes a divider, and a table run is replaced by a real rendered `<table>` (parsed cells, GFM column alignment, header emphasis) — and moving the caret into a construct restores its raw syntax, exactly like the native live preview. A caret sitting exactly at a construct's END (the click-into-block position at doc end) counts as being AFTER it — the trailing table/bold stays rendered instead of flipping back to source. Obsidian's own live-preview extension set is bound to its internal editor component and cannot be mounted on an outside view, so this is a CM6 decoration port (`src/editor/livePreview.ts`): decoration-only (document text, block model and saved file untouched), fence-aware (nothing decorates inside code fences). The table widget comes from a StateField (CM6 forbids plugins from providing decorations that replace line breaks) as a non-block replace (a block widget covering the entire document degenerates line rendering), and clicking the rendered table places the caret inside it so the raw rows return for editing (the widget opts out of `ignoreEvent`; CM's own mousedown handler would otherwise swallow the event first). Live preview is ALWAYS on — it no longer follows the app's Default-editing-mode setting; the block context menu gains **Source mode**, which mounts that block's editor without the extension for one raw-source edit session (committing returns the block to live-preview editing). Works in the in-place embed editor too.

### Fixed

- **Block property display: the reading state now matches the editing state exactly.** The leftover property chips (the `[P]`/`[A]` priority badge, scheduled 📅, deadline ⏰ — rendered next to the block text in the reading state only) are removed; one display serves both states. The props row under a block now renders one dimmed `key:: value` line per property — the same shape and color as the editor's property lines — and both the property NAME and the VALUE render as pages: clicking either opens/creates that page (Logseq parity). The page-props block renders the same clickable lines.
- **Unlinked mentions show their source file.** The unlinked-references panel groups its rows by source file with the same file-name group header (icon + path, click to open) the linked panel uses. Clicking a row VIEWS the source (jump to the block when it has an id, otherwise open its page — same as linked mentions); converting to a `[[link]]` is the explicit link icon at the row end.
- **Markdown tables render as real tables in block content.** Two compounding gaps: (1) Obsidian's table CSS is scoped to `.markdown-rendered` / `.cm-embed-block`, which block content is not, so an inserted table rendered as an invisible grid (no borders, empty cells collapsing to zero width) — block content now styles tables with the theme's own table variables (borders, cell padding, header background, hover) and empty cells keep a minimum width. (2) GFM tables only parse when the header row starts a new block, but Logseq-format files keep table rows hugging the block's first line, so every table in a Logseq-written file rendered as literal pipe text — a render-only transform inserts the required blank line before detected tables (fence-aware, delimiter-row-validated; the block model and saved file stay untouched).
- **Native slash commands that insert or format now take effect (insert table, insert horizontal rule, …).** A `/` menu pick executes the command through the block editor's `Editor` adapter — whose Proxy silently no-op'd every method it didn't implement, so `editor:insert-table`, `editor:insert-horizontal-rule` and a long tail of sibling commands did nothing. All of them are now ported from the native editor implementations onto the adapter, operating on the live CM6 state: table insert (exact native snippet + caret, appended at line end after a blank line on non-empty lines), horizontal rule (one newline at column 0, two otherwise so `---` never joins text), footnote (ref at the caret, definition appended — numbered by live-doc scan), math block / code block (`$$`/code fences around the line), callout (quote the affected lines, selection on the `[!NOTE]` token), bold/italic/code/highlight/strikethrough/comment/math toggles (marker pair + `__`/`_` alternates, word under an empty caret, unwrap when already wrapped), headings 0–6 with the native `sP` semantics (plain lines get the prefix inserted — that is what makes H1–H6 work on ordinary text), quote toggle per line, and the CM5-style `exec()` table (goUp/goDown/goLeft/goRight/goStart/goEnd, deleteLine, swapLineUp/Down — implemented locally since @codemirror/commands 6.11 lacks them — indentMore/Less) behind `indentList`/`unindentList`. Still inert by Obsidian's own design: `editor:insert-wikilink`/`insert-link`/`insert-embed` guard on `instanceof` of the internal native editor class (the built-in `[[` / embed slash items cover them), and fold commands have nothing to fold in a block outline.
- **Escape reliably commits the block edit.** Escape keystrokes never reached CM6's keymap inside Obsidian's host DOM (a capture-phase handler marks them handled first), so pressing Esc after typing — including a fresh `key:: value` property line — silently dropped the edit. The block editor now catches Escape in the capture phase: if a completion popup is VISIBLE it just closes the popup (native behavior); otherwise it commits the edit synchronously, bypassing the host focus bookkeeping that could be stale. Gating on the completion state being merely "pending" (the accept-pass tail that runs ~75 ms after typing) was the trap that made edits typed right before Esc vanish.
- **Bottom references render once.** The unlinked-mentions section was drawn twice after the references area gained its collapsible chrome — once inside the Linked references body (a leftover direct render) and once in its own Unlinked references subsection. The leftover render is gone; unlinked mentions now appear only in the Unlinked references subsection.
- **Block properties render once, not twice.** Every non-task property was drawn twice — as a generic badge next to the block text AND as a row under the block. The generic badges are gone (priority / scheduled / deadline task chips remain), and while a block is being edited the props row is hidden entirely, since the editor already shows the properties as `key:: value` text lines. Reading state now shows the properties exactly once (the props row), editing state exactly once (the editor lines).
- **Nested multi-line code blocks align with Logseq.** The fence-body consumer stripped a single indent unit from every body line regardless of the block's depth, so a code block nested two levels deep kept two stray tabs on every line and rendered pushed right inside its box. Body lines are now dedented to the block's content column (marker depth + 1 unit — Logseq's convention, the same column the serializer writes): column-indented lines render flush, and indentation beyond the column survives as the code's own internal indent. Top-level blocks behave exactly as before; the round-trip stays byte-stable.
- **Bottom references scroll with the page.** The Linked/Unlinked references section was mounted outside the block-editor scroller, so once its content exceeded the leftover viewport space it was clipped by the container and could not be scrolled to (the scroller itself had nothing more to scroll). The section now renders inside the scroller after the outline and scrolls with the page content like Logseq's references; the outline keeps its scroll-comfort gap and the references end the page.

### Changed

- **External changes: editor always wins.** The conflict modal (version picker) is removed. When a file changes on disk while the block editor holds unsaved edits, the editor's content silently re-saves over it — the pre-edit original stays recoverable via the automatic session/pre-write backups. Without unsaved edits the external version is adopted as before.

### Removed

- **Page-embed add-block input row**: the `![[Page]]` embed box no longer shows the "Add a block to …" input at its bottom — page embeds render the source page only (rows remain click-to-edit in place). The backing append path (`appendBlockToPage` / `appendTopLevelBlock`) and its styles were removed with it.
- `ConflictModal` and the line-diff module (`src/features/conflictModal.ts`, `src/features/lineDiff.ts`, their unit tests and styles).
- **Row/bullet/embed highlights.** The hover background on outline rows and embed rows, the editing block's gray background, the bullet dot's hover glow ring, and the embed region's guide line + background are all gone — the outline renders flat: no highlight on the current row, a plain muted bullet, and embeds that look like the surrounding blocks (the breadcrumb, scroll cap and broken-embed error text remain).

- 275/275 unit tests (68 new since v0.2.4: completion source behavior, block-property text helpers, bare-line/structural-raw parsing, properties-as-first-block round-trip, table blank-line separation, live-preview decoration collection). Real-Obsidian E2E: dedicated completion probe 11/11, native slash insert probe 10/10 (menu-picked insert table on empty & non-empty blocks and horizontal rule; registry-executed toggle-bold, insert footnote/math block, set-heading-2, swap-line-up), table render probes (insert-flow empty/line-end tables + pre-written Logseq-format table render as real grids), live-preview probe 10/10 (bold/heading/wikilink/table/hr render while the caret is away and return to raw under the caret), regression 55/55 (acceptance, iter, iter2, iter3 01–07 — props-as-first-block, block props, page embed, syntax, bare-line normalization + tag-as-page, full native selection context menu incl. submenus + editor-menu event + a live Highlightr second-panel test, embed Tab/Shift+Tab indent — UX, edge, parity). ## [0.2.4] — 2026-09-22

Embed-Enter fix (completed), page-props empty-state affordance, unlinked-mentions section.

### Fixed

- **Enter on an embedded block still only committed**: the v0.2.3 wiring was half-done — `startEmbedEdit` never passed the `onCommitAndNew` callback, so the embed's Enter fell back to plain commit. Now wired; semantics refined: Enter below an embed creates a NEW EMPTY BLOCK in the **host page**, directly below the block containing the embed (cross-file and same-file embeds behave identically), and focuses it. Verified live: new block inserted at the host index, focused, persisted.
- **Embed resolve race**: `resolveEmbed` gave up when the vault-wide index hadn't scanned the target file yet (fresh vaults, recently created blocks); it now retries once after 300 ms before showing the is-broken state.

### Added

- **Unlinked mentions section** (`src/features/unlinkedMentions.ts`): below the linked mentions, the page bottom now lists blocks whose plain text mentions this page's title without an existing `[[link]]` (title ≥ 3 chars, occurrence count per row, ±40-char context preview, max 50 rows).
- **One-click convert**: clicking an unlinked mention rewrites the first bare occurrence into `[[title]]` through the guarded write path (backup + operation log); the mention leaves the list on the next index refresh; lines already containing the title inside a `[[ ]]` are never double-linked.

### Verification

## [0.2.3] — 2026-09-22

Editing-flow round: Enter behavior parity, page/block backlinks UI, block props display, editable page properties.

### Fixed

- **Enter exited the editor instead of creating a block**: two stacked root causes. ① `manifest.json` was saved with a UTF-8 BOM by a PowerShell write, so Obsidian failed to parse it and the whole plugin silently didn't load (`loaded: false` — takeover, commands, everything). ② With the plugin actually loading, CM6 fires a spurious `blur` right after the initial editor mount when the Electron window is not OS-focused; the view committed and tore the editor down on that phantom blur. Both fixed: BOM stripped (and all repo JSONs audited), and `onFocusedBlur` now re-checks focus on the next task before committing — a real blur still commits instantly.
- Enter now behaves Logseq-style everywhere: split at caret, new block focused below, embedded-block Enter creates a sibling below the source block (same-file embeds; cross-file embeds commit only).

### Added

- **Page-bottom backlinks section**: `N linked mentions` header under the outline, grouped by source page (icon + path, click to jump), each row shows marker + text and jumps to the referencing block via its `id::`.
- **Block-level backlinks**: blocks referenced via `((id))` get a count badge on the row's right side; click expands an inline panel directly under the block listing each referencing page/block with a jump link; independent expand/collapse per block, multiple panels can be open at once, counts update live on index rebuilds.
- **Block properties row**: `key:: value` pairs render under the block content (skip-list: `id`, `collapsed`, `style` are shown by their own UI affordances instead).
- **Editable page-properties card**: the page-props header is now editable — pencil enters edit mode with key/value inputs per row, delete buttons, an add-row, Save/Cancel; writes go through the guarded write path (automatic backup + operation log) and the view reloads from disk after saving.

### Verification

- 208/208 unit tests; real-Obsidian E2E 37/37: iteration suite 6/6 (Enter persistence, mid-block split, page-bottom backlinks, badge expand/collapse, props row, page-props editing) + regression suites 31/31 (acceptance 8, edge 13, parity 6, UX 4).

## [0.2.2] — 2026-09-22

UX round: last-node indent fix, reading-mode typography parity, self-drawn slash & angle command menus.

### Fixed

- **Last node could not be indented**: blocks created/promoted after the last root registration (Enter/split at page end, outdent/move to top level) were missing from the sibling registry, so Tab silently did nothing. `siblingsOf` now falls back to structural lookup over registered root arrays (7 new unit tests incl. single-node, deep-nested, restore-path edge cases).
- **Reading mode line spacing much larger than editing mode**: static markdown renders inherited Obsidian's `.markdown-rendered` paragraph margins and line-height. The whole static subtree is now pinned to the editor's vertical rhythm (line-height 1.55, paragraph gap 0; lists/headings/quotes/code tuned to match).

### Added

- **Self-drawn command menu** (`src/features/commandMenu.ts`): CM6's tooltip layer does not render inside the host DOM (verified: even built-in `[[` completions produced zero tooltip nodes), so `/` and `<` now open an own-DOM menu with type-to-filter, ↑↓ navigation, Enter/Tab execute, Esc/outside-click close.
- `/` slash commands (33): TODO/DOING/DONE, priorities, scheduled/deadline, headings, divider, code block, quote, bold/italic/highlight, today's date, current time, page link, block ref, embed, queries, indent/outdent/new-block/delete-block structure commands, template vars.
- `<` angle commands (16): HTML snippets (div/span/br/mark/u/sub/sup/kbd/center/font/details) and entities (&nbsp;/&lt;/&gt;/&amp;/&copy;).
- Prose safety: a bare `<` between words (`x < y`) is never rewritten; menus only trigger at line-start/whitespace.

### Verification

- 208/208 unit tests; real-Obsidian E2E: UX 4/4 (last-node indent + persistence, slash menu, angle menu, typography metrics), acceptance 8/8, edge-vault 13/13, parity 6/6.

## [0.2.1] — 2026-09-22

Logseq md 版功能对齐轮（本地交付，不涉及 GitHub/市场/org-mode/DB）。

### Added

- **Tags panel**（`logseq-tag-panel` 视图 + "Open the tags panel" 命令）：全库 #tag 标签云，点击过滤，点击块跳转。
- **Journal prev/next navigation**："Open previous/next daily note" 命令，日期锚定当前打开文件（YYYY-MM-DD / YYYYMMDD 文件名），跨月/年/闰年安全（`src/core/journalDate.ts` 纯函数 + 6 项单测）。
- **Page properties card**：文件首屏 `key:: value` 属性渲染为只读卡片（不进大纲、不改磁盘）。
