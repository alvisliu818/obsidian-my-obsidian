# 仓库协作规则

> 本文件规定本仓库的默认开发交付方式。

## 开发交付

> 用户未另行指定时，开发完成后直接合并到 `main` 并推送，不创建 PR（合并请求）。

- 开发使用独立任务分支。
- 合并前同步远端 `main`，确认工作区没有无关的未提交改动。
- 完成代码审查，并运行 `npm test`、`npm run lint` 和 `npm run build`，全部通过后提交改动。
- 将任务分支合并到主仓库的 `main`，验证合并结果后推送到 `origin/main`。
- 推送后确认本地 `main`、`origin/main` 与远端主分支指向同一提交。
- 仅在用户明确要求时创建 PR，用户指定的其他交付方式同样优先。
- 合并和推送不包含正式发布，用户未要求发布时不创建或推送版本标签。
