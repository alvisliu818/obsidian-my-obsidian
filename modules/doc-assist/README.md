# Obsidian Doc Assist

[English](#english) | 简体中文

在 Obsidian 里提供一套「文档加工流水线」：长文精读提炼、剪藏清洗、双链网状整理、AI 深度赋能、多任务对照写作、资源瘦身。

移植自思源笔记插件 [siyuan-doc-assist](https://github.com/famotime/siyuan-doc-assist)，按 Obsidian 的文件与双链模型重新设计交互，不改变 Obsidian 原有使用习惯。

## 场景一：长文精读与重点提炼

- **全要素关键信息提取**：扫描当前文档，侧边栏聚合一级～六级标题、`**加粗**`、`==高亮==`（Obsidian Highlights）、`*斜体*`、行内代码与代码块、`#标签`、`[[双链]]` 与块引用
- **多维筛选**：按要素类型多选过滤；同一行的多个要点合并为一条；支持分组折叠与即时刷新（文档保存/切换自动重扫）
- **平滑跳转**：点击侧栏条目，编辑器滚动定位到对应行（标题按层级锚点，普通行按行号；比思源块 ID 定位粗粒度，但覆盖日常精读）
- **一键导出**：把筛选后的要点复制/导出为结构化 Markdown；联动 Obsidian Canvas——按「标题 → 要点」层级生成 `.canvas` 概念导图（思源版联动「无界」画布的对应物）

## 场景二：网页剪藏与 AI 报告清洗（✅ v0.2 已落地）

12 个编辑器命令（命令面板搜 "Doc Assist"）。清洗类命令作用域 = 有选区用选区、否则全文档；替换统一走编辑器撤销栈，Ctrl+Z 整体回退；代码块（```/~~~）内容一律不动。

**清洗**
- 去除多余空行（连续空行合并为一行）
- 去除行尾空白
- 剪藏列表前缀（`- • text` / `1. 1. text`）
- AI 报告残留：Deep Research 类报告的数字脚注上标、`^^` 标记、引用标记 `[^1]`、行尾来源链接（表格行保护 `|`）、隐藏 span、重复分隔线
- 中英文标点互转（按内容自动判向；`3.14`、`1,000` 数字间标点保护）
- 中英文之间加空格（盘古空格，URL 跳过）

**整理**
- 合并选区为列表：段落行转列表项、已列行规范化 marker（首行 `1.` 判定有序则整体重编号）、删除空行与孤立圆点行
- 单换行转段落 / 段落转单换行（选中范围）
- 中英双语段落拆分：一段中英混排拆成两段（恰好一次语言切换才拆）

**删区间**（带确认弹窗）
- **断尾求真**：从当前段落（含）删到文档末尾，清理剪藏文末的推广引流
- **删前段**：文首删到当前段落（含）；自动跳过 frontmatter；开篇 10 行内若有 `---` 分隔线，分隔线之前的概要区受保护

## 场景三：双链网状整理与主题沉淀

- **关联文档一键结构化**：把当前笔记的反向链接文档（或正向链接文档）批量移动到以当前笔记命名的文件夹下（思源「移动为子文档」的 Obsidian 对应物——Obsidian 无子文档概念，用文件夹+链接结构表达）
- **智能增量插入**：「插入反链列表 / 插入出链列表」先比对正文已有链接，只追加新条目，不产生重复
- **链接⇋嵌入互转**：`[[链接]]` 与 `![[嵌入]]` 批量互转（思源「链接⇋引用」的对应物；块级 `![[doc#^id]]` 引用转换列为后续）
- **死链标示**：基于 `metadataCache.unresolvedLinks` 给失效双链加删除线样式提示（只读预览层，不改动原文）
- **重复文档识别**：同文件夹下同名不同扩展、或内容哈希相同的文档配对展示，对比后合并删除
- **大文件盘点**：Top 100 大文件报告（文件体积 + 关联附件体积）

## 场景四：AI 深度赋能（OpenAI 兼容 API）

- **逐段翻译**：识别英文段落，AI 翻译后以引用块插入原段下方
- **图片文字识别 (OCR)**：调用视觉模型识别正文或选区中的图片（长图自动切片），以引用格式插入提取文字
- **更好的标题**：提炼多组标题候选，弹窗微调后一键替换（文件名 + 文首 H1）
- **一键摘要 / 概念地图**：生成摘要插入文首；串联出链与反链文档输出层次化概念地图（Markdown 大纲或 Canvas）
- API 地址 / Key / 模型在设置页配置（骨架已就绪），仅存本地

## 场景五：多任务对照写作

- **对照浮窗**：把选中段落或整篇文档投射为置顶浮动面板，半透明可调，完整 Markdown 渲染
- v1 先做应用内浮动窗（拖拽/置顶/透明度）；跨窗口独立悬浮窗（Electron Popup）列为后续评估项
- 浮窗内即时编辑，改动实时写回源文件

## 场景六：资源瘦身与图片智能优化

- **批量转 WebP / PNG**：压缩当前文档或文件夹内图片（Canvas 编码，体积减 60%~80%，原图可选保留或替换）
- **按显示尺寸重采样**：读取图片在笔记中的实际渲染尺寸，等比缩放重存
- **删除本文档图片**：一键移除所有图片链接与嵌入，并清理无引用的附件文件

## 与思源版的关键差异

| 维度 | 思源版 | 本插件 |
| --- | --- | --- |
| 数据模型 | 块树（块 ID 精确定位） | Markdown 文件 + 行号/标题锚点定位 |
| 高亮 | 字体色/背景色/整段色 | `==高亮==` 单一语法（扩展多色列为后续） |
| 子文档 | 文档树层级 | 同名文件夹 + 链接结构 |
| 引用 | 链接⇋块引用 | `[[链接]]` ⇋ `![[嵌入]]`，块引用 `^id` 后续支持 |
| 画布 | 联动第三方「无界」 | 原生 `.canvas`（JSON）直接生成 |
| 撤销 | 事务回滚 | 编辑器命令天然进撤销栈 / `vault.process` |
| AI | 兼容 OpenAI 格式 | 同（设置页已就绪） |

## 安装

- 手动安装：将 `main.js`、`styles.css`、`manifest.json` 放入 `<vault>/.obsidian/plugins/obsidian-doc-assist/`
- 社区插件市场上架列入路线图

## 开发

```sh
npm install
npm run build   # tsc 检查 + esbuild production 产物
npm run dev     # watch 模式
npm test        # tsc 检查 + core 冒烟测试（tests/smoke-core.ts，14 例）
```

E2E 冒烟探针（tests/e2e/smoke.mjs）依赖 playwright connectOverCDP，在已部署插件的测试库实例（CDP 9259）上运行，覆盖：命令注册、清洗/整理/删区间命令端到端、ConfirmModal 交互、单撤销步回退。

源码分层沿用思源版的架构约定：`core/`（纯逻辑，可单测）→ `services/`（Obsidian API 适配）→ `plugin/`（动作编排与生命周期）→ `ui/`（视图与对话框）。
